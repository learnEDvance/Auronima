# Auronima — Event System

## Purpose

The Event System is the central execution engine of Auronima.

Its responsibility is to ensure that every requested action is executed in the correct order until all required work has been completed.

The Event System contains the world's execution order.

It does not define object behavior.

It only determines when behavior is executed.

---

# Core Architecture

The Event System is organized as a centralized execution tree.

Every trigger creates a new execution tree whose root is the command generated by that trigger.

For the duration of its execution, this tree becomes the only active execution context.

The Event System never executes commands outside the currently active execution tree.

Every command executed belongs to this tree or is generated by one of its descendants.

The active tree is processed until no executable commands remain.

Only then may another execution tree become active.

---

# Triggers

A trigger represents the beginning of an execution sequence.

Triggers may originate from:

* user interactions
* completion of another command
* timers
* animations
* scheduled operations
* system requests

A trigger creates one or more root commands.

These commands form the root of a new execution tree.

---

# Commands

Commands are execution requests.

Each command targets exactly one object.

A command describes **what** operation should occur.

The target object determines **how** that operation is performed.

Examples include:

* Expand Object
* Collapse Object
* Set Page
* Set Timestamp
* Move Camera
* Reveal Object
* Hide Object
* Update Layout

Commands never directly execute work on other objects.

---

# Object Execution

When a command is executed, it is passed to its target object.

The target object updates its own internal state.

If additional work is required as a consequence of that state change, the object returns additional commands describing the required follow-up work.

The Event System inserts these commands into the current execution tree.

Each returned command becomes a child of the command that produced it.

This process continues recursively until the current execution tree contains no remaining executable commands.

---

# Execution Scope

The currently executing tree defines the complete scope of execution.

Only commands belonging to this tree are eligible for execution.

Commands that belong to unrelated execution trees are never processed while another tree is active.

If an object determines that work is required outside the current execution tree, that work is **not** executed immediately.

Instead, the object registers the required command with the appropriate execution branch.

The command remains pending until that branch becomes the active execution tree.

The Event System never leaves the current execution tree in order to process unrelated work.

This guarantees deterministic execution and prevents unrelated updates from interrupting one another.

---

# Dependency-Based Execution

Commands are executed according to their dependencies.

A command becomes eligible for execution only when all of its required parent work has completed.

The Event System determines execution order based on dependency relationships within the active execution tree.

Execution never depends on unrelated branches elsewhere in the system.

---

# Responsibilities

The Event System is responsible for:

* receiving triggers
* creating execution trees
* maintaining execution order
* executing commands
* receiving newly generated child commands
* inserting commands into the appropriate execution tree
* processing commands only within the active execution tree
* completing one execution tree before beginning another

The Event System contains no object-specific knowledge.

Objects remain responsible for their own behavior.

The Event System is responsible only for executing that behavior in the correct order.

---

# Design Goal

The Event System acts as the execution authority for the entire Auronima world.

Every trigger establishes a temporary execution root.

From that root, commands propagate only through their own dependency tree.

The Event System resolves that tree completely before moving to another, while any work belonging to other execution trees is safely recorded for later execution.

This allows the world to remain deterministic, modular, and efficient without requiring the Event System to reason about unrelated parts of the world during execution.
